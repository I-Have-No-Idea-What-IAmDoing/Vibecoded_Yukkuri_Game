## Note 1 (2026/4/13):

I’ve been meaning to write like a diary or whatever to like make note of my experience on AI coding as a skeptic. 
But considering I am using AI, I’ve just been a lazy bastard and haven’t done that.
Anyway, I’ve been positively surprised at the competence, but it’s also really dumb still. 
I started by using Google Jules, then Google Antigravity, then Copilot. 
If you wonder why such a weird timeline, it’s because I’ve been just using whatever free AI I can get since I am not spending money for this experiment, lmao.

Even after a couple of months of "working" on and off, there have been times where I just stopped working because I got bored lol. The game is still pretty basic. There are a lot of bugs that I can't fix along with major performance issues.
I think it went beyond my expectations on what AI can do, but it still can’t make a game by itself.

I think I am going to try and create a new branch to remake the game in Rust using Bevy to see how that would be.
Part of that is just that the game can't handle being run on my laptop. I am also hoping that Rust’s stronger safety might get rid of some bugs. Along with the package ecosystem.

The biggest problem with the game is that the AI can't really program the Yukkuri AI right. There have been so many pathfinding issues and behavior trees fuck-ups that make the game just not work.

Other things I noticed was that AI coding has definitely gotten better with each new model release. Not only more reliable but that they can code new things.
LLM vision still sucks for anything precise, which is bad for an audio-visual medium.
Google Jules is ridiculously generous with its limit that I have never hit even when I try to waste tasks. 
It also has a sensible and understandable budget, which is nice. 
Though I think it's definitely worse at actually coding than the others though.
