# Design: Force-Based Hopping Movement System

## 1. Introduction
The current Yukkuri Movement System relies on setting velocity directly on Pymunk bodies (`PhysicsSystem`) via steering behaviors (`BehaviorSystem` -> `MoveToTarget`). While functional, it lacks the "weight" and characteristic "hopping" movement associated with Yukkuris. The movement feels like sliding on ice or floating.

This design proposes a complete overhaul to a **Force-Based Hopping System**, where movement is generated by applying impulses (hops) rather than setting continuous velocity. This will integrate deeply with `YukkuriStats` to reflect agility, stamina, and energy.

## 2. Core Mechanics

### 2.1. Hopping Physics
Instead of continuous movement, Yukkuris will move in discrete hops.
- **Impulse Application**: Movement is driven by `body.apply_impulse`.
- **Friction/Damping**:
    - **Grounded State**: High damping/friction. The Yukkuri stops quickly after landing.
    - **Airborne State**: Low damping. The Yukkuri maintains momentum while "in air" (simulated).
- **Z-Axis Simulation**: Although the game is 2D top-down, we will simulate a `z` (height) value for visual feedback (scaling/shadow) and logic (cannot change direction while mid-hop).

### 2.2. The Hop Cycle
A single hop consists of four phases:
1.  **Prepare (Pre-Hop)**: A short delay where the sprite might squash. Energy is committed.
2.  **Launch**: Impulse applied. `z_velocity` is set positive. State becomes `Airborne`.
3.  **Airborne**: Entity moves based on physics. `z` changes by `z_velocity`. Gravity affects `z_velocity`. No steering control allowed (except maybe minor air control for high agility).
4.  **Land**: `z` returns to 0. Velocity is damped heavily. Impact event triggered (sound, dust). Recovery delay based on stats.

### 2.3. Stat Integration
Movement parameters will be derived dynamically from `YukkuriStats`.

| Stat | Effect |
| :--- | :--- |
| **Energy** | Fuel for hopping. Low energy = shorter hops, longer recovery. |
| **Health** | Injured Yukkuris hop feebly. |
| **Agility (New?)** | Derived from `Growth Stage` + `Health` + `Athleticism` (if added). Affects hop frequency and height. |
| **Weight** | Derived from `Growth Stage` + `Fullness`. Heavier Yukkuris have more momentum but need more force (Pymunk handles mass, but we need to tune impulse). |

## 3. Architecture Changes

### 3.1. Components
*   **New Component: `Locomotion`**
    *   `state`: Enum (IDLE, PRE_HOP, AIRBORNE, LANDING)
    *   `hop_charge`: float (0.0 to 1.0)
    *   `z_height`: float
    *   `z_velocity`: float
    *   `target_velocity`: Vector2 (Desired direction/speed from AI)

*   **Update Component: `YukkuriStats`**
    *   Add properties/methods to calculate `move_speed_modifier`, `jump_power`.

### 3.2. Systems
*   **Update: `PhysicsSystem`**
    *   Handle Z-axis gravity integration (manual Euler integration for `z`).
    *   Apply ground friction only when `z <= 0`.
*   **New System: `MovementSystem`**
    *   Replaces the direct velocity setting in `MoveToTarget`.
    *   Reads `Locomotion.target_velocity`.
    *   Manages the Hop Cycle (Prepare -> Launch -> Land).
    *   Applies Impulses to `PhysicsBody`.
    *   Consumes `Energy` from `YukkuriStats`.

### 3.3. AI / Behavior
*   **Update: `MoveToTarget` Action**
    *   Instead of calculating `velocity` and setting it on `PhysicsBody`, it calculates `desired_velocity` (steering) and sets it on the `Locomotion` component.
    *   The `MovementSystem` then decides *how* to achieve that velocity (by hopping).

## 4. Visuals & Feedback
*   **Squash & Stretch**: Driven by `Locomotion` state (Squash on Pre-Hop and Land, Stretch on Launch).
*   **Shadow**: Drawn offset by `z_height`.
*   **Dust Particles**: Spawned on Land.

## 5. Benefits
*   **Game Feel**: "Bouncy" movement fits the creature theme perfectly.
*   **Gameplay**: Stamina management becomes real. Chasing/fleeing becomes more dynamic (bursts of speed vs. steady pace).
*   **Visuals**: Natural integration of squash/stretch animations.
